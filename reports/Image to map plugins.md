# Paper 26.3 picks URL map plugins

**ImageFrame and ImageOnMapReborn are the only widely documented, currently maintained Paper plugins that both claim Minecraft 26.3 and deliver a one-command image-URL workflow with explicit multi-map size options for item-frame murals on this stack; Frameify and Image-To-Painting are strong newer peers with the same version pin, while Fabric Image2Map is irrelevant here.** This server runs **Paper 26.3-258 on Java 25** with **Geyser Standalone + Floodgate**, is **not Folia**, and is **plugin-only** with **no image/map plugin in live `minecraft/plugins/`**; unused legacy `data/` still holds **SushiImage-0.5** from an earlier phase ([server_context.md](../research_notes/Image%20to%20map%20plugins/server_context.md)). Geyser does translate filled-map packets to Bedrock, but dense or animated custom maps repeatedly disconnect, OOM, or incapacitate Bedrock clients, so “works on Paper 26.3” is not enough for a hybrid Java/Bedrock box ([Geyser supported versions](https://geysermc.org/wiki/geyser/supported-versions/); [Geyser #6569](https://github.com/GeyserMC/Geyser/issues/6569)). Upstream ImageOnMap stopped at 1.17-1.18; DrMap’s public listings stop at 1.21.x; Custom Images is excellent for Java wall art but packet-based and Geyser-risky; SushiImage 0.5.1 claims 26.3 but is file-load-and-click, not URL-to-items ([ImageOnMap releases](https://github.com/zDevelopers/ImageOnMap/releases); [DrMap Modrinth](https://modrinth.com/plugin/drmap); [Custom Images](https://www.spigotmc.org/resources/custom-images.53036/); [Map to Image / SushiImage](https://www.spigotmc.org/resources/map-to-image-1-20-6-26-2.136618/)). For this exact server, prefer a **good-quality** 26.3-listed vanilla-map plugin with size params and URL controls, then smoke-test Bedrock under real mural density before enabling GIFs.

## This Paper 26.3 box has no live image-map plugin

The live fingerprint is unambiguous: **itzg/minecraft-server Java 25**, jar **paper-26.3-258**, logs confirm Paper **26.3-258**, single Paper process (not Folia), Geyser Standalone plus Floodgate Spigot **2.2.5-b141**, and **no `mods/` directory** ([server_context.md](../research_notes/Image%20to%20map%20plugins/server_context.md)). Live plugins are the usual ops set (Chunky, CoreProtect, EssentialsX, FAWE, GriefPrevention, LuckPerms, Multiverse, WorldGuard, floodgate, spark) with **zero** image-to-map jars installed. Unused legacy `data/plugins/` retains **SushiImage-0.5.jar** plus a `SushiImage/` config tree (`sushiimage.db`, `Images/`), matching earlier ARCHITECTURE/DEPLOY history; that jar’s `plugin.yml` names the plugin **SushiImage** `0.5` by NogginTime with command `image` and permission `sushiimage.admin` ([server_context.md](../research_notes/Image%20to%20map%20plugins/server_context.md); [Spigot Map to Image](https://www.spigotmc.org/resources/map-to-image-1-20-6-26-2.136618/)). Compatibility target is therefore **Paper/Bukkit API 26.3**, Bedrock via Geyser matters, and Folia support is a maintenance signal only.

Minecraft **26.3** also changed map-adjacent APIs: explorer maps became distinct items, `minecraft:map_color` was removed, and Paper still deprecates fragile `MapMeta.setMapId` while keeping `MapView`/`MapRenderer` ([26.3 Snapshot 7](https://feedback.minecraft.net/hc/en-us/articles/47877771669133-Minecraft-Java-Edition-26-3-Snapshot-7); [Paper MapMeta 26.3](https://jd.papermc.io/paper/26.3/org/bukkit/inventory/meta/MapMeta.html)). That raises the bar for “still works” claims from 1.21-era jars and explains why late-2026 releases that explicitly list **26.3** outrank older marketplace pages.

## Command UX splits URL posters from wall placers

The operator goal - “run a command with an image URL and get map item(s), ideally with size options, for item frames” - is not what every 26.3-tagged plugin actually ships. **ImageFrame** requires a name and WxH: `/imageframe create <name> <url> <width> <height>`, with `selection` placing into pre-selected frames and `combined` handing a one-click mural item that treats the clicked frame as **top-left** ([Hangar ImageFrame](https://hangar.papermc.io/LOOHP/ImageFrame)). **ImageOnMapReborn** preserves classic `/tomap <url> resize 4 3` (also `4x3`), plus dither flags and a splatter/poster that hangs from the **bottom-left** empty frame ([ImageOnMapReborn](https://github.com/Optiblur/ImageOnMapReborn)). **Frameify** mirrors ImageFrame-style naming with richer delivery flags (`deliver=individual|fill|none`) and grids up to **64×64**, baking pixels into vanilla `map_*.dat` so static maps can survive plugin removal ([Modrinth Frameify](https://modrinth.com/plugin/frameify)). **MapImage** is the cleanest “URL → inventory tiles” one-liner (`/mapimage <url> 2x4`) but lists only through **26.2** and re-downloads URLs on every restart ([Modrinth MapImage](https://modrinth.com/mod/mapimage)).

**DrMap** stays survival-flavored: hold an empty map, `/drmap create <url> height:2 width:3`, then place with optional magic-fill that respects GriefPrevention/WorldGuard ([Modrinth DrMap](https://modrinth.com/plugin/drmap)). **Image-To-Painting** uses `/itp render` then separate place/frame commands and stresses **direct** image URLs ([Hangar Image-To-Painting](https://hangar.papermc.io/Depletion1/Image-To-Painting)). **Custom Images** takes URL or file with **percent scale**, pastes packet entities rather than trading vanilla map items, and gated URL create behind `images.command.create.url` after SSRF/path fixes ([Custom Images](https://www.spigotmc.org/resources/custom-images.53036/)). **SydMontague ImageMaps** is download-then-place; use GitHub **1.0.12**, not the stale Spigot 1.0.10 jar ([ImageMaps 1.0.12](https://github.com/SydMontague/ImageMaps/releases/tag/1.0.12)). This server’s leftover **SushiImage 0.5** only exposes `/image load <file> [size_percent]` against files under `plugins/SushiImage/Images/`; marketplace **0.5.1** adds a 26.3 claim but does not document a URL create path in the researched materials ([Map to Image](https://www.spigotmc.org/resources/map-to-image-1-20-6-26-2.136618/)).

On animation and limits, **ImageFrame**, **ImageOnMapReborn**, and **Frameify** advertise animated GIFs; DrMap and MapImage accept GIF formats without animation; Custom Images / SydMontague / SushiImage lack documented animated playback ([Hangar ImageFrame](https://hangar.papermc.io/LOOHP/ImageFrame); [ImageOnMapReborn](https://github.com/Optiblur/ImageOnMapReborn); [Modrinth Frameify](https://modrinth.com/plugin/frameify); [Spigot DrMap](https://www.spigotmc.org/resources/drmap.87368/)). ImageOnMapReborn’s new-install defaults (`download.block-private-addresses`, size/pixel/GIF caps) and ImageFrame’s optional URL whitelist / creation limits / packet rate limit are the clearest abuse controls among URL fetchers ([ImageOnMapReborn](https://github.com/Optiblur/ImageOnMapReborn); [ImageFrame config.yml](https://raw.githubusercontent.com/LOOHP/ImageFrame/main/common/src/main/resources/config.yml)).

## Geyser Bedrock risk reshapes Paper fitness

Geyser aligns with this stack (Bedrock **26.40-26.65**, Java **26.3**) and does implement map-item data translation, including historical fixes for blank item-frame maps ([Geyser supported versions](https://geysermc.org/wiki/geyser/supported-versions/); [JavaMapItemDataTranslator](https://github.com/GeyserMC/Geyser/blob/64bb3993/core/src/main/java/org/geysermc/geyser/translator/protocol/java/level/JavaMapItemDataTranslator.java); [Geyser #385](https://github.com/GeyserMC/Geyser/issues/385)). Floodgate only handles Bedrock identity; it does not improve map rendering ([Floodgate wiki](https://github.com/GeyserMC/Geyser/wiki/Floodgate/f4fa39c2b1f9517af7da0c7729b1ad709a688a45)).

The failure mode that matters is volume and animation. Open **Geyser #6569** (Jul-Oct 2026) reports Bedrock players “incapacitated” by ImageFrame maps, including non-animated ones; a Geyser maintainer called Bedrock map handling “atrocious” and video-like map updates likely a can’t-fix ([Geyser #6569](https://github.com/GeyserMC/Geyser/issues/6569)). Related ImageFrame issues cover render-distance disconnects (`End of stream`) and animated-map proxy OOM; config knobs `Hooks.Geyser.DisableSmoothAnimationForBedrockPlayers` and `MapPacketSendingRateLimit` mitigate but do not erase the class of bug ([ImageFrame #123](https://github.com/LOOHP/ImageFrame/issues/123); [ImageFrame #45](https://github.com/LOOHP/ImageFrame/issues/45); [ImageFrame config.yml](https://github.com/LOOHP/ImageFrame/blob/main/common/src/main/resources/config.yml)). Custom Images has a Jul 2025 Bedrock visibility break after Netty pipeline changes on 1.21+ ([Custom Images discussion](https://www.spigotmc.org/threads/custom-images.302109/page-40)). Emage’s custom packet GIF pipeline should be treated as higher Bedrock risk until proven otherwise ([Spigot Emage](https://www.spigotmc.org/resources/emage.130410/)). No primary-source Geyser issue threads were found specifically naming ImageOnMapReborn, Frameify, DrMap, MapImage, SydMontague ImageMaps, or SushiImage - absence of reports is **not** proof of Bedrock safety.

## Ranked recommendation for Paper 26.3 + Geyser

Among **good-quality** picks (version-aligned, maintained, and actually able to turn a URL plus size into item-frame maps), **ImageFrame 2026.1.5** ranks first for documented Paper **26.3** support, create/place/combined UX, Folia-capable maintenance signal, ImageOnMap/DrMap migration, and install-base scale - with the hard caveat that it has the **worst documented Geyser Bedrock pain**, so this hybrid server should ship static murals only, enable Geyser animation disable and packet rate limits, and keep tile counts low until tested ([Hangar 2026.1.5](https://hangar.papermc.io/LOOHP/ImageFrame/versions/2026.1.5); [Geyser #6569](https://github.com/GeyserMC/Geyser/issues/6569)). **ImageOnMapReborn 1.2.x** ranks second: explicitly tested on Paper **26.3**, familiar `/tomap` plus WxH plus animated GIF with SSRF/size hardening, Folia unsupported (irrelevant here); the quality gap is **very new / low adoption**, so production confidence is thinner than ImageFrame despite cleaner security defaults on paper ([ImageOnMapReborn](https://github.com/Optiblur/ImageOnMapReborn); [Spigot](https://www.spigotmc.org/resources/imageonmapreborn.139800/)). **Frameify** ranks third: explicit **26.3** plus **Java 25+** Paper/Purpur, URL WxH, deliver modes, baked vanilla maps, animated GIF/WebP - tempered by **ARR** licensing, thinner public issue/download signals, and **unverified** Geyser behavior ([Modrinth Frameify](https://modrinth.com/plugin/frameify)).

Just below that tier sit good 26.3 plugins whose workflow or Bedrock fit is weaker for the stated goal. **Image-To-Painting 1.4.0** has a solid Hangar 26.3 pin and multi-map place/frame tools but less of a single WxH create command and likely no GIF ([Hangar Image-To-Painting](https://hangar.papermc.io/Depletion1/Image-To-Painting)). **SydMontague ImageMaps 1.0.12 from GitHub** (not the stale Spigot 1.0.10 jar) offers MIT-licensed vanilla frames and a proper 26.x fix via download-then-place rather than one-shot URL create ([ImageMaps 1.0.12](https://github.com/SydMontague/ImageMaps/releases/tag/1.0.12)). **SushiImage 0.5.1** is the only prior art already on this host’s unused data and does claim 26.3, but local **0.5 is file-based**, closed-source, and low-download - an upgrade path for familiarity, not the best URL-command fit ([Map to Image](https://www.spigotmc.org/resources/map-to-image-1-20-6-26-2.136618/); [server_context.md](../research_notes/Image%20to%20map%20plugins/server_context.md)).

**Merely available** candidates need jar smoke-tests before trust. **MapImage 2.0** has the cleanest URL-to-items syntax but **no 26.3 listing**, restart URL dependency, and RAM warnings ([Modrinth MapImage](https://modrinth.com/mod/mapimage)). **DrMap** is simple empty-map art with public versions through 1.21.11 and 26.x only via an informal Discord jar ([DrMap](https://modrinth.com/plugin/drmap); [Spigot thread](https://www.spigotmc.org/threads/drmap.480868/)). **Custom Images 2.5.12** is excellently maintained for Java 26.3 wall art but wrong for map-item handouts and has **known Geyser breakage** ([Custom Images](https://www.spigotmc.org/resources/custom-images.53036/)). **MapPaint**, **ReColorfulMap**, **Emage**, and Modrinth **ImageMaps** land last among installable options: paint-studio focus, wrong version pin, packet GIF risk, or an abandoned one-shot jar ([MapPaint](https://hangar.papermc.io/BbIJABNPOBATEJb/MapPaint); [ReColorfulMap](https://hangar.papermc.io/zhangyuheng/ReColorfulMap); [Emage](https://www.spigotmc.org/resources/emage.130410/); [Modrinth ImageMaps](https://modrinth.com/mod/imagemaps)).

Exclude for this stack: upstream **ImageOnMap 4.2.2**, Fabric **Image2Map**, and stale 1.21-only tools (ImageCanvas, Image Map Plus, URLIMAGETOOMAPART, Custom Maps) ([ImageOnMap releases](https://github.com/zDevelopers/ImageOnMap/releases); [Image2Map](https://modrinth.com/mod/image2map)).

**Explicit unverified gaps:** no plugin was runtime-tested on **Paper 26.3-258 + Geyser Standalone + Floodgate** in this survey; Standalone vs Spigot Geyser map failure rates are unknown; DrMap’s Discord 26.1+ jar was not fetchable as a durable release; Frameify/Image-To-Painting/ImageOnMapReborn Bedrock mural behavior is unproven; SushiImage **0.5.1** URL capabilities vs local **0.5** were not jar-diffed; ImageFrame `MaxSize: 100` units and several license/SPDX edge cases (DrMap GitHub license null, Custom Images LICENSE 404, Frameify ARR policy fit) were not compliance-audited; no third-party security audit of any candidate’s HTTP client was found.

## Conclusion

The decision for this host is no longer “which image map plugin exists,” but “which 26.3 Paper plugin survives Geyser under the mural density you actually want.” ImageFrame remains the feature and maintenance champion, yet its own issue tracker is the strongest argument for trying ImageOnMapReborn or Frameify first if Bedrock players will stand in front of large walls. Reusing SushiImage from unused `data/` only makes sense as a short-term familiarity bridge after upgrading to 0.5.1 - it does not satisfy the URL-command requirement documented for 0.5. The next useful experiment is a controlled Bedrock soak of one static 2×2 and one denser mural on the top pick, with GIF left off until that pass is clean.
